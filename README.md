# NEXA Web P2P — النسخة التجريبية 0.1

تطبيق ويب تقدمي (PWA) للمراسلة النصية المباشرة بين متصفحين باستخدام WebRTC Data Channels.

## ما الذي يعمل في هذه النسخة؟

- واجهة عربية RTL متجاوبة بطابع داكن بسيط.
- تثبيت كتطبيق PWA على الأجهزة المدعومة.
- إنشاء غرفة دعوة برمز قصير.
- انضمام مستخدم ثانٍ برمز الغرفة.
- تبادل SDP Offer/Answer عبر Vercel Function.
- استخدام STUN لاكتشاف مسارات الاتصال.
- نقل الرسائل النصية عبر WebRTC Data Channel مباشرة بين الطرفين.
- حفظ سجل الرسائل محلياً في المتصفح.

## ما الذي لا تدعمه هذه النسخة؟

- لا توجد حسابات أو دليل مستخدمين مركزي.
- لا توجد رسائل مؤجلة أو تسليم عندما يكون الطرف الآخر غير متصل.
- لا توجد إشعارات دفع موثوقة عند إغلاق الصفحة.
- لا يوجد TURN؛ لذلك قد تفشل الاتصالات في بعض الشبكات أو خلف بعض أنواع NAT.
- لا يوجد تشفير تطبيقي مستقل أو تحقق موثوق من هوية الشخص. WebRTC يستخدم DTLS لحماية النقل، لكن هذا لا يثبت وحده هوية الطرف الآخر.
- سجل المحادثة محلي في المتصفح، وليس متزامناً بين الأجهزة.
- لا توجد حالياً مرفقات أو مكالمات صوت/فيديو.

## كيف تعمل البنية؟

1. الواجهة: HTML + CSS + JavaScript عادي، دون إطار عمل.
2. الباك إند: Vercel Function واحدة في `api/signal.js`.
3. التخزين المؤقت للإشارات: Upstash Redis REST مع TTL قدره 10 دقائق.
4. بعد تبادل SDP، تنتقل الرسائل عبر WebRTC Data Channel ولا تمر عبر Vercel أو Upstash.

**لماذا Upstash؟** لأن Vercel Functions عديمة الحالة؛ لا يمكن الاعتماد على ذاكرة العملية لتبادل SDP بين استدعاءات مختلفة. Upstash يحفظ بيانات التفاوض مؤقتاً فقط. لا تضع مفاتيح Upstash في ملفات الواجهة.

## النشر عبر GitHub وVercel

### 1) إنشاء قاعدة Upstash Redis

1. افتح https://console.upstash.com/
2. أنشئ قاعدة Redis جديدة.
3. من قسم REST انسخ:
   - REST URL
   - REST Token (Standard token)
4. لا تضع هذه القيم في `app.js` أو أي ملف داخل الواجهة.

### 2) رفع المشروع إلى GitHub

1. فك ضغط `NEXA-Web-P2P.zip`.
2. أنشئ مستودع GitHub جديداً.
3. ارفع محتويات المجلد إلى جذر المستودع، بحيث يكون `index.html` و`api/` في الجذر مباشرة، وليس داخل مجلد فرعي إضافي.
4. تأكد من ظهور `api/signal.js` في المستودع.

### 3) ربط GitHub بـ Vercel

1. افتح https://vercel.com/new
2. اختر Import Git Repository.
3. اربط حساب GitHub إذا طُلب منك ذلك.
4. اختر مستودع NEXA.
5. اترك Framework Preset على Other.
6. اترك Build Command وOutput Directory فارغين؛ المشروع static مع Vercel Function.
7. اضغط Deploy.

Vercel ينشر ملفات `api/` كوظائف Functions تلقائياً.

### 4) إضافة متغيرات البيئة

من مشروعك في Vercel:
1. Settings → Environment Variables.
2. أضف `UPSTASH_REDIS_REST_URL` بقيمة REST URL.
3. أضف `UPSTASH_REDIS_REST_TOKEN` بقيمة Standard REST Token.
4. اختر Production وPreview عند الحاجة.
5. احفظ المتغيرات.
6. اذهب إلى Deployments ثم أعد نشر آخر Deployment (Redeploy)، لأن المتغيرات لا تُطبق على النشر السابق.

### 5) اختبار الموقع

افتح رابط Vercel المنشور. جرّب من جهازين أو متصفحين منفصلين:
1. على الجهاز الأول اضغط «إنشاء دعوة».
2. شارك رمز الغرفة مع الجهاز الثاني.
3. على الجهاز الثاني اضغط «الانضمام إلى محادثة» وأدخل الرمز.
4. انتظر حالة «متصل مباشرة».
5. أرسل رسالة من كل جهاز.

اختبر أولاً على نفس شبكة Wi-Fi، ثم جرّب Wi-Fi مقابل بيانات الهاتف.

## ملاحظات أمان وتشغيل

- استخدم HTTPS فقط؛ Vercel يوفره للنطاقات المنشورة.
- رمز الغرفة عشوائي بطول 48 بت، وتوكنات الجلسة عشوائية أقوى. تعامل مع الدعوة كسر مؤقت ولا تنشرها علناً.
- بيانات SDP قد تتضمن عناوين IP مرشحة للاتصال؛ يتم حفظها مؤقتاً في Upstash لمدة 10 دقائق.
- لا تضع Standard REST Token في الواجهة أو GitHub.
- هذه نسخة أولية وليست جاهزة للإنتاج العام دون مراجعة أمنية واختبارات حمل وحدود استخدام ومكافحة إساءة الاستخدام.
- يفضّل إضافة حدود معدل الطلبات قبل نشرها للجمهور.
- عند فشل الاتصال المباشر، لن يتم استخدام TURN تلقائياً؛ ستظهر للمستخدم رسالة فشل.

## الملفات

- `index.html`: بنية الواجهة.
- `styles.css`: التصميم المتجاوب.
- `app.js`: منطق الواجهة وWebRTC.
- `api/signal.js`: نقطة API لتبادل بيانات الإشارات المؤقتة.
- `manifest.webmanifest`: تعريف PWA.
- `sw.js`: التخزين المؤقت للملفات الثابتة.
- `vercel.json`: إعدادات Vercel.
